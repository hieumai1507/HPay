How a payment works

Request, confirm, then a workflow does the rest

A transfer is not one database write. It is a short chain of steps that can fail in the middle, so each step is recorded and can be undone.

  1. RequestThe app asks for a transfer. Limits and fees are checked and shown.
  2. ConfirmThe user enters a PIN. Bigger amounts ask for a code or a second factor.
  3. Reserve and checkFunds are held and fraud rules run.
  4. PostTwo ledger lines are written in one transaction: money out, money in.
  5. NotifyBoth people are told. If a step failed, earlier steps are compensated.

Built to be trusted

Rules you can set, decisions you can read

Limits, fees and the checks each amount needs are configured per plan, not hard-coded. Behind them, money software fails in the gaps: a retry, a crash between two writes, two requests at once. Each gap that mattered has a decision record, and each bug that got through has a record with its root cause and the test that now guards it.
