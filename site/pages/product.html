Customer · mobile app

Everyday money, with safeguards you do not have to think about

The app is built with Expo and React Native. These are the screens that exist in the code today.

Sign up and sign in

Phone number and password, a one-time code, and a session that renews itself. If a renewal token is used twice, every session is closed.

Identity check (KYC)

Photograph an ID card and a selfie. A vision model scores them, borderline cases go to a human reviewer, and a verified account gets higher limits.

Top up

Add money from a simulated bank with a code. Retrying never credits twice.

Send money

Pick a person, see the fee, confirm with a PIN, and follow the payment on a progress screen.

Request money and split a bill

Ask someone to pay you back with a note, or split a bill across a group and watch who has paid.

QR code

Show a code so anyone can pay you without typing a phone number.

Savings vaults

Set money aside in named vaults, with an optional round-up on each payment.

Security settings

Set or reset the PIN, and turn on a second factor (TOTP) for larger amounts.

Business · mobile app

Two people sign before money moves

A company opens a business wallet. One member, the maker, proposes a payout. One or more checkers must approve it, each with a one-time code. Which payouts need which approvals is set by a policy, and that policy is edited in the admin console.

  • Approval levels: a payout can need a level 1 signature, then a level 2 signature.
  • A policy is versioned. A new version only applies to orders created after it is saved.
  • An order waiting for approval keeps the policy it was created under.
Operations · admin console

The back office for staff who keep it running

A React console with role-based access. A superadmin sees everything; an operations user sees the queues they work. A full guide for non-technical staff, with 36 annotated screenshots, is in the repository.

Review identity documents

A queue of applications the AI could not decide. The reviewer sees the photos, the score and the reasons, then approves or rejects with a reason. Keyboard shortcuts move through the queue.

Watch every payment

Each payment is a workflow with steps. The monitor shows its status and age. A failed payment can be retried or compensated by someone with permission; a payment waiting for approval is marked as such.

Reconcile balances

Compare each wallet balance with the sum of its ledger lines and see any difference. The ledger is the source of truth; a wallet that disagrees with it is a bug to be found, not a number to be adjusted.

Configure services without code

The service catalog describes how each kind of payment runs: its validations, its action pipeline and how it posts to the ledger.

Plans, limits and authentication tiers

A plan sets the per-payment, daily and monthly limits for each service and a minimum gap between payments. A matrix decides what each amount needs: a PIN for small amounts, a code for medium ones, a second factor for large ones.
