# gen-feature-hook — Query/mutation hook backed by the generated contract

## Project conventions (MUST follow)

- One folder per domain: `src/features/<domain>/hooks.ts` (`kyc`, `fraud`,
  `workflow`, `recon`, `orgs`, `ai`, `audit`).
- Never hand-write request/response types when the contract has them. Import from
  the generated `src/api/schema.d.ts`. Type missing or wrong? Fix
  `hpay-backend/api/openapi.yaml` first, then `npm run gen:api` — never patch the
  generated file. (Many admin responses are only described as free-text in the spec;
  a local interface next to the hook is acceptable ONLY for those, with a comment
  pointing at the openapi path.)
- All requests go through `api<T>()` from `src/api/client.ts` — it injects the JWT,
  maps `{code,message}` errors to `ApiError`, and clears the session on 401 (A03).
  Never raw `fetch` in a hook.
- **Queries**: `useQuery` with a real array `queryKey` (`['kyc', status]`,
  `['recon', date]`). Auto-refresh pages pass `refetchInterval` (workflow 10s,
  fraud 30s) here, not in the page.
- **Mutations**:
  - Money-adjacent or state-transition POSTs (review, resolve, decide, run recon,
    save policy) accept an `Idempotency-Key` header where the backend supports it —
    generated by the calling page once per intent, threaded through, never per click.
  - No `retry` overrides — a mutation must never silently double-fire.
  - `onSuccess` invalidates exactly the affected keys; a 409 (`ApiError.status === 409`)
    is NOT an error toast case for queues — surface it so the page can update the row
    in place (A01). The 409 payload carries the new state in `ApiError.payload`.
- Hooks never format user-facing strings — pages render `ApiError.message`.

## Steps

1. Confirm the endpoint in `hpay-backend/api/openapi.yaml` (STOP if missing —
   contract-first).
2. `npm run gen:api` if the contract changed; check `src/api/schema.d.ts`.
3. Write the hook; export a `toneFor(status)` Badge helper here if the domain has
   status chips.
4. `npm run typecheck && npm run lint`.

## Checklist

- [ ] No raw fetch, no hand-written types the contract already provides
- [ ] queryKey consistent with the other hooks of the domain
- [ ] Mutation invalidates affected keys; 409 propagated for in-place row update
- [ ] refetchInterval set here for auto-refresh pages
