Solution Architecture — hpay-admin (React)

Dashboard vận hành nội bộ: KYC review, giám sát gian lận, theo dõi workflow, đối soát. Người dùng là nhân viên vận hành — ưu tiên mật độ thông tin, thao tác nhanh bằng bàn phím, và audit đầy đủ. UI chi tiết xem ../design/ui-design-spec.md.

1. Stack

Layer Công nghệ Lý do
Framework React 18 + Vite + TypeScript strict SPA thuần, không cần SSR (app nội bộ sau VPN)
UI kit shadcn/ui + Tailwind Khớp design tokens Figma, table/dialog/form đủ
Router TanStack Router Type-safe route + search params (filter lưu trong URL)
Server state TanStack Query Polling queue, invalidation sau action
Table TanStack Table Server-side sort/filter/pagination
Chart Recharts Dashboard metrics
API client Sinh từ api/openapi.yaml Cùng contract với mobile
Form react-hook-form + zod

3. RBAC nội bộ

Role admin Quyền
viewer Xem tất cả, không action
kyc_reviewer Duyệt/từ chối KYC
risk_officer Xử lý fraud flags, khóa tài khoản
ops Retry workflow, xem recon, export
superadmin Tất cả + quản lý admin users

FE ẩn action theo role (UX), backend vẫn là nơi enforce thật (backend doc §3.2). Mọi action ghi audit_logs kèm lý do bắt buộc nhập (reject KYC, khóa tài khoản phải có reason ≥ 10 ký tự).

4.1. Dashboard

KPI cards (user mới, txn count, volume, tỉ lệ fail) + chart volume theo giờ + panel "cần chú ý": KYC chờ > 1h, fraud flags open, workflow stuck > 5 phút, recon lệch hôm qua. Mỗi panel click-through sang queue tương ứng.

4.2. KYC Review

  • 3 tab theo ai_verdict: auto_approved (chỉ xem/spot-check), manual_review (queue chính), rejected.
  • Detail: 2 ảnh cạnh nhau (URL ký 5 phút), ai_score + ai_reasons hiển thị như checklist gợi ý, thông tin user, lịch sử KYC trước đó.
  • Action: Approve / Reject (+ reason). Phím tắt A/R/J/K di chuyển queue — reviewer xử lý hàng loạt nhanh.
  • Case cover: 2 reviewer mở cùng 1 hồ sơ → optimistic lock (updated_at làm version), người sau nhận conflict và refresh.

4.3. Fraud Monitor

  • Queue fraud_flags open: cột rule_code, score, txn ref, user, tuổi flag. Row expand xem reasons (giải thích LLM + rule hits).
  • Action: Mark safe (clear) / Confirm fraud → dialog chọn hệ quả: khóa tài khoản, đảo giao dịch (nếu chưa completed thì hủy workflow, nếu completed thì tạo reversal — gọi đúng API backend, FE không tự quyết logic).
  • SLA hint: flag > 30 phút chưa xử lý tô đỏ.

4.4. Workflow Monitor (điểm sáng demo)

  • Bảng instance: filter theo status (running, waiting_approval, failed, compensating), definition, thời gian kẹt.
  • Instance detail: timeline dọc từng step_executions — attempt, input/output JSON (viewer có collapse + copy), error, thời gian. Đúng tinh thần observability của base doc.
  • Action theo state: Retry step (failed), Force fail + compensate (kẹt manual), có confirm + reason. Disable đúng theo state machine — FE đọc allowed_actions từ API thay vì tự suy.

4.5. Reconciliation

  • Danh sách runs theo ngày: matched/mismatched, badge kết quả.
  • Run detail: bảng items filter theo result; panel tóm tắt AI (backend sinh); nút export xlsx (backend trả file, FE chỉ tải).
  • Case cover: run đang chạy → trạng thái running + auto-refresh; ngày chưa có run → nút trigger thủ công (role ops).

4.6. Organizations & Policies

  • CRUD org, members (gán maker/checker + level), policies (dải tiền + tiers builder dạng visual: kéo số approvals mỗi level).
  • Hiển thị cảnh báo khi sửa policy: "Lệnh đang chờ giữ policy snapshot cũ" — đúng semantics backend E09.

4.7. Audit Log

Bảng đọc-only, filter theo actor/action/resource/khoảng thời gian. Immutable — không có nút gì ngoài export.

5. Edge cases FE vận hành

# Tình huống Xử lý
A01 Action đúng lúc record đổi state (nơi khác xử lý rồi) Backend trả 409 + state mới → FE toast + cập nhật row tại chỗ, không reload cả bảng
A02 Queue dài, reviewer đang ở trang 3, dữ liệu mới đẩy vào Server-side pagination theo cursor, không dùng offset (tránh trôi hàng)
A03 Token admin hết hạn giữa phiên review Refresh single-flight như mobile; fail → modal re-login giữ nguyên URL + filter (đều trong search params)
A04 Ảnh KYC URL ký hết hạn khi đang xem Ảnh lỗi → auto xin URL mới 1 lần, hơn nữa thì báo
A05 2 tab trình duyệt cùng thao tác Mutation nào cũng dựa version/state check ở backend; FE xử lý 409 thống nhất qua interceptor
A06 Export xlsx nặng Backend job async → FE poll + notification khi sẵn sàng, không treo UI
A07 JSON input/output của step chứa PII Backend mask sẵn trước khi trả (***), FE không nhận raw — không thể leak từ DevTools

6. Bảo mật app nội bộ

  • JWT audience admin, TTL ngắn (10 phút) + refresh; idle 15 phút → khóa màn hình.
  • CSP nghiêm (không inline script), không lưu gì vào localStorage ngoài UI prefs — token giữ trong memory + refresh cookie httpOnly (SameSite=Strict).
  • Route guard theo role; mọi trang có RequireRole wrapper.
  • Không có "God mode": kể cả superadmin cũng đi qua audit log.
