# Admin app

## Tech stack (package.json)

React 18.3, react-router-dom 7, Vite 5, TypeScript 5.9, TanStack Query 5 and Table 8, zustand 5, Tailwind 3 (plus `src/ui/tokens.css`), lucide-react icons. Dev tools: eslint 9, Playwright 1.62 (e2e), openapi-typescript 7 (`npm run gen:api`). Scripts: `dev`, `build` (`tsc --noEmit && vite build`), `typecheck`, `lint`, `test:e2e`. There is no unit-test runner (no vitest/jest); the only tests are Playwright specs in `e2e/` (audit, dashboard, edge-cases, fraud, kyc, login, my-tasks, orgs, recon, workflow), run in CI by `admin-ci.yml`.

Dev server on 5173 and preview on 4173 both proxy `/v1` and `/healthz` to `http://localhost:8080` (`vite.config.ts`). `VITE_API_URL` overrides the base URL (`api/client.ts:4`).

## Routing and guards (`router.tsx`)

`createBrowserRouter`: `/login` (public) and `/` wrapped in `<RequireAdmin><Layout/></RequireAdmin>` with `errorElement`; `*` renders a 404 `ErrorPage`. Children (each lazy-loaded with `Suspense`): `dashboard`, `kyc`, `kyc/:id`, `fraud`, `workflows`, `workflows/:id`, `tasks`, `recon`, `services`, `offers`, `offers/:id`, `orgs`, `ai-settings`, `audit`; index redirects to `/dashboard`.

`RequireAdmin` (`features/auth/RequireAdmin.tsx`) only checks that a token exists in the store; otherwise `Navigate` to `/login` with `state.from` (path + search, preserving filters). It does NOT check the role, the token expiry or the backend. Route-level role gating does not exist: every authenticated admin can open every page. Sidebar entries are the same 11 links for all roles (`ui/Sidebar.tsx`).

## State

- `stores/admin.ts`: zustand store `{token, admin, setSession, clearSession, can}`. Persisted in `sessionStorage` key `hpay-admin-session` (dies with the tab). `AdminRole` = `viewer | kyc_reviewer | risk_officer | ops | superadmin`, matching the DB enum. `can(permission)` is a static role to permission map (`kyc.review`, `fraud.resolve`, `workflow.action`, `recon.run`, `orgs.edit`, `ai.manage`, `admins.manage`); the file states it is UX-only. Only two call sites use it: `KYCDetailPage.tsx:44` (`kyc.review` enables review buttons) and `MyTasksPage.tsx:39` (`workflow.action` enables approve/reject). Fraud resolve, recon run, org policy edit, AI settings, service and offer editing are not gated in the UI.
- Server state: TanStack Query. Some hooks poll (workflows every 10 s, fraud flags every 30 s).
- `stores/toast.ts`: toast queue.

## Data layer

`api/client.ts` exports `api<T>(path, {method, body, headers, signal})` (alias `apiRequest`). It adds `Authorization: Bearer <admin token>`, JSON-encodes the body, treats 204 as `undefined`, and on non-2xx throws `ApiError(status, code, message, payload)` using the backend `{code, message}` envelope. A 401 clears the session (the guard then redirects to login). There is no refresh flow for admin (the backend has none). `schema.d.ts` is generated by `scripts/gen-api.ts` from the OpenAPI file; the script points at `../../hpay-backend/api/openapi.yaml` (a legacy path, the spec is now `src/backend/api/openapi.yaml`), so regeneration from this repo layout needs the path fixed.

## Auth and session handling

Login posts email and password and stores `{access_token, admin}` in the store/sessionStorage (`LoginPage.tsx:43-49`). The admin JWT lives 15 minutes (same `AccessTokenTTL`), there is no refresh and no silent re-login: after expiry the next call returns 401, the store clears and the guard redirects to login. Logout is local only (no endpoint).

## Mock-data fallbacks present today

Dashboard KPIs and volume chart (always mock), recon (on error), orgs (on error), audit (on error), AI keys and settings (on error, plus fake success on write), fraud mapper invented fields. All other list hooks return an empty list/page on error rather than surfacing it (KYC, fraud, workflows, services), so a backend outage looks like "no data". These are product risks: operators can act on mock data. Tracked in audit section 2 (admin).
