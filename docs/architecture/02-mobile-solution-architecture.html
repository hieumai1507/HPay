Solution Architecture — hpay-mobile (React Native / Expo)

Client người dùng cuối của HPay. Doc này định nghĩa kiến trúc app, navigation, state, security client-side, và cách xử lý các tình huống mạng/giao dịch mà một ví điện tử thật phải cover. UI chi tiết xem ../design/ui-design-spec.md.

1. Stack

Layer Công nghệ Lý do
Framework Expo SDK (React Native, TypeScript strict) Build/OTA update nhanh, đủ native module cần
Navigation expo-router (file-based) Deep link sẵn (mở app từ notification duyệt lệnh)
Server state TanStack Query Cache, retry, polling — hợp mô hình giao dịch async
Client state Zustand (nhẹ) Chỉ giữ session + UI state, không nhét server data
Form react-hook-form + zod Schema validate chia sẻ được với API DTO
API client Sinh từ api/openapi.yaml (openapi-typescript + fetch wrapper) Contract-first, không viết tay endpoint
Secure storage expo-secure-store (Keychain/Keystore) Token không bao giờ nằm trong AsyncStorage
Camera/QR expo-camera, expo-barcode-scanner KYC + scan QR

4. Xử lý giao dịch phía client — các case bắt buộc cover

# Tình huống Xử lý
M01 User double-tap nút "Chuyển tiền" Disable nút ngay khi tap + Idempotency-Key sinh 1 lần cho cả flow confirm (UUID tạo lúc vào màn confirm, không tạo lúc bấm)
M02 Request timeout / mất mạng sau khi bấm chuyển KHÔNG hiển thị "thất bại" vội — chuyển sang màn Processing, poll GET /transactions/:refCode bằng chính idempotency retry; timeout poll 30s → "Đang xử lý, kiểm tra lại ở Lịch sử"
M03 Transaction async chưa xong (workflow đang chạy) Màn Processing poll 1s→2s→4s (backoff); trạng thái pending_approval hiển thị riêng "Chờ doanh nghiệp phê duyệt"
M04 Access token hết hạn giữa flow Interceptor tự refresh (single-flight, queue request chờ); refresh fail → về Login nhưng GIỮ draft form
M05 Refresh token bị revoke (đăng nhập máy khác / theft detection) Force logout + thông báo rõ lý do
M06 Số tiền nhập Chỉ nhận integer VND, format ngăn cách nghìn khi gõ, chặn paste ký tự lạ; parse bằng string→BigInt, không bao giờ đi qua float JS
M07 App vào background lúc đang ở màn OTP/confirm Che mờ toàn bộ nội dung ứng dụng bằng hiệu ứng Blur bản xứ (Native Blur) nhằm bảo mật thông tin nhạy cảm của người dùng (giống VCB Digibank) khi ứng dụng chuyển sang chế độ Task Switcher (background). OTP còn TTL thì giữ, hết thì báo xin lại.
M08 Deep link "duyệt lệnh" khi chưa login Lưu pending route → login xong điều hướng tiếp
M09 Checker mở lệnh đã bị người khác duyệt xong/từ chối UI xử lý ERR_ALREADY_FINALIZED: refresh inbox, toast trạng thái mới
M10 Ảnh KYC mờ/tối Kiểm tra client-side (blur/brightness heuristic) trước khi upload, hướng dẫn chụp lại — giảm vòng lặp reject
M11 Upload KYC rớt mạng giữa chừng Upload 2 ảnh tách phần, resume theo request id; trạng thái draft lưu local
M12 Danh sách lịch sử dài Cursor pagination + FlashList; pull-to-refresh không nhảy vị trí

5. Security client-side

  • Token trong SecureStore; không log token/OTP; console.log bị strip ở production build.
  • Certificate pinning (expo-ssl-pinning) cho domain API — demo được điểm phỏng vấn mobile security.
  • Root/jailbreak detection (expo-device heuristics) → chỉ cảnh báo, không chặn (portfolio).
  • Che screenshot ở màn nhạy cảm (OTP, số dư) trên Android (FLAG_SECURE), iOS che khi vào app switcher.
  • Session idle 5 phút → yêu cầu biometric/passcode local (expo-local-authentication) để mở lại tab Home.
  • QR nhận tiền chứa payload ký (HMAC từ server) gồm user_id + phone masked — client bên kia verify qua API, không tin nội dung QR thô.

6. Kết nối Backend

  • Base URL theo env (dev/staging/demo) qua app.config.ts.
  • Mọi request gắn header: Authorization, X-Device-Id, X-Request-Id (uuid mỗi request), Idempotency-Key (POST tạo giao dịch).
  • Error contract: FE map mã ERR_* (backend doc §3.3) sang message tiếng Việt tập trung tại src/lib/errors.ts — không hardcode message rải rác.
  • Realtime: KHÔNG dùng websocket cho v1 — polling có backoff là đủ và đơn giản; chừa interface TransactionWatcher để sau này thay bằng SSE.
