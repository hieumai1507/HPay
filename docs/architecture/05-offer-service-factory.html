05 — Offer Factory & Service Catalog Architecture (Enterprise Product Engine)

Nguồn cảm hứng: Khung quản trị dịch vụ tài chính Enterprise (Digital Engagement Payment Platform / Offer Factory). Đơn giản hóa thành kiến trúc linh hoạt cho HPay: tách biệt giữa Executable Core (Workflow & Ledger Engine) và Dynamic Product Configuration (Service Catalog, Offer Factory & Authentication Matrix).

1. Tổng quan & Động lực

Trong các hệ thống thanh toán truyền thống, thông số giao dịch (hạn mức, phương thức xác thực PIN/OTP, trạng thái bật/tắt dịch vụ) thường bị mã hóa cứng (hardcode) trong logic xử lý của từng API. Điều này gây khó khăn khi vận hành:

  • Muốn tạm khóa một dịch vụ (ví dụ: bảo trì tính năng Chuyển tiền P2P hoặc Rút tiền) phải sửa code backend hoặc cấu hình gateway.
  • Khó khăn trong việc phân hạng gói sản phẩm khác nhau giữa Khách hàng Cá nhân (Personal Customer Level 1, 2) và Doanh nghiệp (Business Starter, Enterprise).
  • Yêu cầu xác thực (PIN vs OTP vs 2FA) bị cố định, không linh hoạt điều chỉnh theo ngưỡng rủi ro tiền tệ.

Kiến trúc Offer Factory & Service Catalog giúp Admin Ops dễ dàng cấu hình toàn bộ các quy tắc này trên Admin UI mà không cần khởi động lại Server hay sửa code Backend.

3. Database Schema (Delta)

Thiết kế bảng dữ liệu bổ sung trong PostgreSQL hỗ trợ Service Catalog và Offer Factory:

-- 1. Danh mục Dịch vụ (Service Catalog)
CREATE TYPE service_status AS ENUM ('active', 'maintenance', 'disabled');
CREATE TABLE services (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    code           VARCHAR(50) UNIQUE NOT NULL,       -- P2P_TRANSFER, MONEY_REQUEST, ORG_DISBURSEMENT
    name           VARCHAR(100) NOT NULL,
    category       VARCHAR(50) NOT NULL,              -- transfer, payment, org, wallet
    status         service_status NOT NULL DEFAULT 'active',
    action_priority VARCHAR(20) NOT NULL DEFAULT 'before_gl', -- before_gl | after_gl
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 2. Gói Sản phẩm / Phân hạng Đối tượng (Offer Factory)
CREATE TYPE offer_role AS ENUM ('customer', 'agent', 'merchant', 'biller', 'operator');
CREATE TABLE offers (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    code           VARCHAR(50) UNIQUE NOT NULL,       -- OFFER_CUST_L1, OFFER_CUST_L2, OFFER_BIZ_ENT
    name           VARCHAR(100) NOT NULL,
    role           offer_role NOT NULL DEFAULT 'customer',
    level          INT NOT NULL DEFAULT 1,            -- Level 1 to 20
    is_active      BOOLEAN NOT NULL DEFAULT true,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 3. Cấu hình Dịch vụ trong Gói Offer (Offer Services & Limits)
CREATE TABLE offer_services (
    id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    offer_id           UUID NOT NULL REFERENCES offers(id) ON DELETE CASCADE,
    service_id         UUID NOT NULL REFERENCES services(id) ON DELETE CASCADE,
    is_enabled         BOOLEAN NOT NULL DEFAULT true,
    min_amount         BIGINT NOT NULL DEFAULT 0,
    max_amount_per_txn BIGINT NOT NULL DEFAULT 100000000, -- 100M VND
    daily_limit        BIGINT NOT NULL DEFAULT 500000000, -- 500M VND
    monthly_limit      BIGINT NOT NULL DEFAULT 2000000000,-- 2 tỷ VND
    interval_seconds   INT NOT NULL DEFAULT 0,            -- Giây tối thiểu giữa 2 GD
    UNIQUE(offer_id, service_id)
);

-- 4. Ma trận Xác thực theo Ngưỡng Tiền (Authentication Matrix)
CREATE TYPE auth_method_enum AS ENUM ('none', 'pin', 'otp', '2fa');
CREATE TABLE offer_auth_matrix (
    id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    offer_service_id UUID NOT NULL REFERENCES offer_services(id) ON DELETE CASCADE,
    min_amount       BIGINT NOT NULL DEFAULT 0,
    max_amount       BIGINT,                            -- NULL = không giới hạn
    auth_method      auth_method_enum NOT NULL DEFAULT 'pin',
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);

4. Luồng Xử lý Runtime (OfferGuard Middleware)

Khi người dùng thực hiện giao dịch trên Mobile hoặc Web, hệ thống kiểm tra qua 4 bước bảo vệ:

sequenceDiagram autonumber actor User as 📱 Mobile App participant Middleware as 🛡️ OfferGuard Middleware participant ServiceDB as 🗄️ Service & Offer Cache participant Engine as ⚙️ Workflow Engine User->>Middleware: POST /v1/transactions/transfer {service_code, amount, pin/otp} Middleware->>ServiceDB: Query Service status & User's Offer Profile ServiceDB-->>Middleware: Return {service_status, limits, auth_matrix} alt Dịch vụ đang bảo trì Middleware-->>User: 403 ERR_SERVICE_MAINTENANCE ("Dịch vụ đang bảo trì") else Vượt hạn mức ngày/tháng Middleware-->>User: 422 ERR_LIMIT_EXCEEDED ("Hạn mức còn lại trong ngày không đủ") else Sai phương thức xác thực Middleware-->>User: 401 ERR_AUTH_METHOD_REQUIRED ("Giao dịch > 5M yêu cầu xác thực OTP") else Hợp lệ Middleware->>Engine: Forward to Workflow Engine Execution Engine-->>User: 201 Created / Processing end

5. Quy hoạch Màn hình Admin Ops (hpay-admin)

Màn hình Admin Chức năng chính APIs Backend
Service Catalog (`/services`) Quản lý danh sách dịch vụ tài chính, bật/tắt trạng thái Maintenance Mode tức thì, xem thống kê số lượng Offer đang dùng service. GET /v1/admin/services
POST /v1/admin/services
PUT /v1/admin/services/:id
Offer Factory (`/offers`) Tạo & Chỉnh sửa gói Offer (Phân hạng Customer / Business), gán danh sách Services được phép truy cập, cấu hình hạn mức giao dịch (Lần/Ngày/Tháng). GET /v1/admin/offers
POST /v1/admin/offers
PUT /v1/admin/offers/:id
Authentication Matrix Manager Cấu hình Ma trận Xác thực linh hoạt (Vd: dưới 2M dùng PIN/Biometrics; từ 2M-50M dùng OTP; trên 50M dùng 2FA PIN+OTP). PUT /v1/admin/offers/:id/auth-matrix
