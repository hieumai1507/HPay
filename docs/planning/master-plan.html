🗺 Master Plan — kế hoạch tổng thể & quy trình thực thi

Kế hoạch tổng cho 3 repo code. Nguyên tắc xuyên suốt: docs-first, và mỗi tính năng trước khi code phải sinh đủ 2 tài liệu trong repo code tương ứng — Implementation Plan + Solution Architecture (diagram bắt buộc là mermaid). Skill gen-feature-plan enforce việc này tự động.

Vị trí tài liệu: nằm trong repo code đang làm (ví dụ src/backend/docs/plans/f3-workflow-engine/), không nằm trong repo docs. Repo docs giữ thiết kế tổng; repo code giữ kế hoạch thực thi của chính nó. Plan viết bằng HTML self-contained (mermaid CDN) đúng chuẩn chung.

Anti-pattern bắt được trong source (để kể khi phỏng vấn): cột tiền của MPRequest khai báo columnType: 'float' — tiền để float trong hệ production thật. Đây chính là lý do rule #1 của fintech-review là cấm float; HPay dùng BIGINT minor units từ DB tới client.

5. Definition of Done (mọi phase)

  • 2 tài liệu plan đã sinh và được duyệt TRƯỚC khi code; nếu code xong lệch plan → cập nhật plan trong cùng PR.
  • Edge case của phase có test tên TestEdge_*, chạy -race, CI xanh.
  • fintech-review trả VERDICT: READY.
  • openapi.yaml cập nhật nếu API đổi; docs repo cập nhật nếu thiết kế đổi.
  • Commit message tiếng Anh, prefix chuẩn (feat:/fix:/docs:/test:).
