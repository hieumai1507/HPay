# Load test, 2026-11-25: US dollars as cents (ADR-0019, spec w6-usd)

Purpose: confirm ledger integrity with the new numbers (AC-10). The change touches amounts, not locking or cost. The numbers below are noisy (a laptop running Docker, Postgres, Redis and the test together) and are not a benchmark.

## Command
```
$env:LOAD_USERS=200; $env:LOAD_WORKERS=50; $env:LOAD_SECONDS=60
.\scripts\test-backend.ps1 -Db usdload1 -GoArgs "-tags loadtest ./test/loadtest -run TestP2PLoad -v -count=1 -timeout 15m"
```
Fresh database `usdload1`, branch `worktree-agent-a1bf9618184c251e1` merged with main. The `hpay-api` container was stopped for the run so only the test's own workers read the Redis streams.

## Amounts
Each user starts with 8,000 cents ($80.00); a transfer is 40 to 399 cents ($0.40 to $3.99); the fee is the flat 25 cents.

## Result (PASS)
| Measure | Value |
|---------|-------|
| Accepted (request plus PIN confirm) | 3,822 ok, 0 failed, 63.0 per second |
| Latency request plus confirm | p50 758 ms, p95 1.10 s, p99 1.30 s, max 1.61 s |
| Settled | 3,796 completed, 26 failed (limit refusals), 0 still processing, in 123.5 s (30.7 completed per second) |
| End to end, created to completed | p50 70.5 s, p95 77.3 s, p99 78.1 s (the workers lag behind the accepting side) |
| Wallets with balance different from ledger sum | 0 |
| User money before / after / fees | 1,600,000 / 1,505,100 / 94,900 cents, delta 0 |

Ledger integrity (AC-10): zero wallets differ from their ledger sum and money is conserved.

## Notes
- An earlier attempt on a shared Redis showed 5,173 transfers stuck in processing and a delta of 50 cents. Cause: the `hpay-api` container was consuming the same Redis streams as the test, so the test's workflows never completed. That run is not counted; no code was changed because of it.
- The old load numbers (dong amounts, 1,000 fee) are not comparable: the fee, amounts and limits differ.
