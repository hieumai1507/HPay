UI Design Spec — HPay (nguồn dựng Figma)

Spec này là bản thiết kế "bằng chữ" đủ chi tiết để dựng Figma file chuẩn: design tokens → components → screens. Khi code FE, dùng Figma MCP (get_design_context, get_variable_defs) đọc ngược từ Figma vào code — vì vậy tên token và component trong Figma phải đặt đúng như spec này để mapping tự động.

1. Cấu trúc Figma file đề xuất

HPay Design
├── Page: 🎨 Foundations      # color/type/spacing variables + styles
├── Page: 🧩 Components        # component library (2 theme: Mobile, Admin)
├── Page: 📱 Mobile            # frames 390×844 (iPhone 15) — flow theo section
├── Page: 🖥 Admin             # frames 1440×900 — mỗi route 1 section
└── Page: 🔀 Flows             # prototype wiring + user journeys

Figma Variables đặt theo tên token dưới đây (collection color, space, radius, type). Component đặt tên Category/Name/Variant (ví dụ Button/Primary/Default).

4. Mobile Screens (390×844) — 24 frames

Flow Auth & KYC (6)

  1. Onboarding — 3 slide value props, CTA Đăng ký.
  2. Register — phone, password (strength meter), checkbox điều khoản.
  3. OTP — OTPInput, đếm ngược 120s.
  4. KYC Intro — 2 bước cần làm, lưu ý ánh sáng.
  5. KYC Capture ×2 — camera full-screen + KYCPhotoFrame overlay, nút chụp lại/dùng ảnh.
  6. KYC Status — 3 biến thể: pending (illustration + "AI đang kiểm tra"), verified, manual_review ("1–2 giờ làm việc").

Flow chính (10)

  1. Home — Header chào + avatar; Card số dư (AmountDisplay display size, nút ẩn/hiện 👁 — mặc định ẨN khi mở app); 4 quick action (Nạp, Chuyển, QR, Lịch sử); "Giao dịch gần đây" 5 TxnListItem.
  2. Transfer: Người nhận — search SĐT (debounce, hiện tên masked khi tìm thấy), nút scan QR, danh bạ gần đây.
  3. Transfer: Số tiền — AmountInput + số dư khả dụng + note; validate hạn mức realtime (hiện "vượt hạn mức KYC tier" nếu có).
  4. Transfer: Xác nhận — bảng tóm tắt (người nhận, số tiền, phí, tổng), cảnh báo nếu người nhận lần đầu; nút "Chuyển tiền" (Loading variant khi bấm — disable ngay, M01).
  5. Transfer: Processing — spinner + timeline rút gọn (Đã gửi → Đang kiểm tra → Hoàn tất); copy đúng trạng thái workflow.
  6. Transfer: Result — 3 biến thể: success (✓ + confetti nhẹ), failed (lý do bằng error map + nút thử lại), pending_approval ("Chờ doanh nghiệp phê duyệt").
  7. Topup ×2 — nhập tiền → OTP → result (tái dùng component).
  8. History — filter chips (Tất cả/Vào/Ra/Đang xử lý), list nhóm theo ngày, FlashList.
  9. Txn Detail — AmountDisplay, StatusBadge, TimelineStep list (public view), ref_code mono + copy, nút "Báo cáo sự cố".
  10. QR nhận tiền — QR lớn nền trắng, tên + phone masked, nút share/save.

Flow Business (6)

  1. Org Switcher — trong Account: chọn ngữ cảnh cá nhân/tổ chức (role hiện rõ: Maker/Checker L1…).
  2. Maker: Tạo lệnh chi — form người nhận + tiền + note; hiển thị PolicyTierRow (view-only) cho biết lệnh sẽ cần ai duyệt.
  3. Maker: Trạng thái lệnh — ApprovalCard + progress từng level, ai đã duyệt lúc nào.
  4. Checker: Approval Inbox — badge số lệnh chờ; list ApprovalCard; empty state "Không có lệnh chờ".
  5. Checker: Chi tiết lệnh — đầy đủ thông tin + lịch sử actions; 2 nút Duyệt (primary) / Từ chối (danger, bắt buộc reason).
  6. Checker: OTP xác nhận — OTPInput; sau khi duyệt hiện kết quả "Đã duyệt — chờ level 2" hoặc "Hoàn tất, giao dịch đang thực hiện" (M09 conflict state cũng vẽ ở đây).

Khác (2)

  1. Account — profile, KYC tier + hạn mức, bảo mật (đổi pass, biometric toggle, thiết bị đăng nhập), Business Wallet entry.
  2. Locked/Idle — màn biometric khi idle 5 phút.

5. Admin Screens (1440×900) — 12 frames

  1. Login — email + password + (mock) 2FA.
  2. Dashboard — 4 KPICard, chart volume 24h, 4 panel "cần chú ý" (§4.1 doc admin).
  3. KYC Queue — 3 tab, DataTable (user, score, verdict, tuổi hồ sơ), phím tắt hint footer.
  4. KYC Detail — split: trái 2 ảnh zoom được, phải info + ai_reasons checklist + form action; thanh queue navigation (J/K) trên cùng.
  5. Fraud Queue — DataTable + row expand reasons; bulk select "Mark safe".
  6. Fraud Detail Dialog — hệ quả chọn radio: clear / lock account / reverse — mỗi lựa chọn có mô tả hậu quả.
  7. Workflow Monitor — filter bar (status, definition, stuck>N phút), DataTable, cột current_step + tuổi.
  8. Workflow Instance Detail — header txn info; timeline dọc TimelineStep full view; mỗi step expand JSONViewer input/output; action bar theo allowed_actions.
  9. Recon Runs — bảng ngày, matched/mismatched badges, nút trigger run.
  10. Recon Detail — KPI matched %, DataTable items filter theo result, panel "AI tóm tắt", nút Export.
  11. Orgs & Policies — master-detail; PolicyTierRow edit mode + banner cảnh báo policy snapshot (E09).
  12. Audit Log — DataTable + filter, read-only.

6. UX rules chung (áp cho mọi screen)

  • Mọi số tiền: tabular-nums, không bao giờ wrap, âm/dương có dấu rõ.
  • Mọi list: đủ Skeleton/Empty/Error state (đã có component).
  • Mọi action nguy hiểm: confirm dialog nêu hậu quả cụ thể, không dùng chữ chung chung "Bạn có chắc?".
  • Mọi trạng thái async: hiển thị đúng ngôn ngữ trạng thái hệ thống (§2.1 mapping) — không sáng tác trạng thái mới ở FE.
  • Timestamp: relative (< 24h) + absolute tooltip; múi giờ Asia/Ho_Chi_Minh.
  • Accessibility: contrast AA, touch target ≥ 44px (mobile), focus ring rõ (admin).

7. Quy trình làm việc với Figma MCP

  1. Dựng Foundations (variables đúng tên token §2) → Components (§3) → Screens (§4–5).
  2. Khi code: get_variable_defs → sinh tokens.ts / Tailwind config; get_design_context từng frame → dựng screen; get_screenshot để so khớp.
  3. Component code đặt tên trùng component Figma → dùng Code Connect map nếu cần.
