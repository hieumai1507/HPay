F8 KYC + AI — Implementation Plan

1. Scope & non-goals

Điểm mấu chốt: KYC chạy như một workflow definition (kyc_verification) trên đúng engine F4 — lần đầu tiên dùng instance KHÔNG gắn transaction (engine đã hỗ trợ sẵn transaction_id = NULL từ F4). Schema kyc_requests có sẵn từ F1. Điểm mới thật sự: storage interface cho ảnh, Claude vision scorer + mock fallback, và admin auth tối thiểu (login + middleware aud=admin) vì master plan F8 yêu cầu "admin review API" mà admin_users chưa có đường đăng nhập.
ShipsKhông làm ở F8
Storage interface + local-dir driver (ảnh lưu KYC_STORAGE_DIR, key = {request_id}/{id_card|selfie}.jpg); signed URL HMAC TTL 5 phút cho admin xem ảnh (doc 01 §3.4); Scorer interface: claudeScorer (Anthropic API qua net/http, vision 2 ảnh, trả JSON score 0–100 + reasons) + mockScorer (deterministic theo hash ảnh — chạy CI/offline không cần key); workflow kyc_verification v1: SCORE (auto, retry 2, timeout 30s) → CLASSIFY (auto: ≥85 auto_approved · 50–84 manual_review · <50 rejected, cập nhật kyc_requests.status + users.kyc_status guarded); API user: POST /v1/kyc/submit (multipart, chặn double-submit), GET /v1/kyc/status; Admin: POST /v1/admin/auth/login (admin_users, argon2id, JWT aud=admin, access-only), GET /v1/admin/kyc?tab=, POST /v1/admin/kyc/:id/review (guarded WHERE status='manual_review' — 2 reviewer đua nhau thì người sau nhận 409, nền tảng cho A01) + audit_logs; migration 000014: seed definition + seed 1 admin user dev; openapi cùng commit; tests đủ 3 nhánh verdict + double-submit + review race + signed URL + mock determinism OCR trích số CMND + mã hóa PII AES-GCM (F8 không trích xuất text nào từ ảnh — scorer chỉ trả score/reasons; cột mã hóa thêm khi có tính năng cần đọc số giấy tờ); MinIO/S3 driver (interface sẵn, driver local đủ demo); refresh token cho admin (access 15' đủ cho SPA dev); notification cho user khi verdict xong; các API admin khác (fraud/recon/My Tasks — F9)

6. Rollout & risk

  • Ảnh ghi trước DB tx: nếu tx fail sau khi ghi file → file mồ côi trong storage dir. Chấp nhận cho local storage (dọn bằng tay/cron sau này); đổi thứ tự sẽ tệ hơn (row trỏ ảnh không tồn tại).
  • claudeScorer không chạy trong CI (không có key) — mockScorer nhận diện qua thiếu ANTHROPIC_API_KEY, log rõ "using mock scorer" lúc boot. Test dùng stub inject trực tiếp, không phụ thuộc cả hai.
  • Admin seed trong migration là dev-convenience — hash argon2id cứng, email cố định; README ghi rõ đổi ở prod. Không log password ở đâu.
  • Score dùng int 0–100 end-to-end (không float — tránh vùng xám với fintech-review #1 dù score không phải tiền).
  • Route /v1/files/kyc/*key mount ở role admin|all (chỉ admin SPA cần xem ảnh).
  • KYC workflow là instance đầu tiên không có transaction — engine đã hỗ trợ từ F4 (NULLIF insert + guard inst.TransactionID != uuid.Nil trong failInstance), rủi ro thấp nhưng test 3 nhánh sẽ phát hiện nếu có góc chết.
