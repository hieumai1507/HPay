Implementation Plan — Approval Detail Endpoint

Feature slug: approval-detail-endpoint · Phần mở rộng của F6 (maker-checker). GET /v1/org/approvals (Inbox), challenge, decide đã có, nhưng chưa có endpoint xem chi tiết 1 request kèm lịch sử chữ ký — cả màn "Trạng thái lệnh" của maker (mockup frame 19) lẫn phần "CHỮ KÝ" của màn checker (frame 21) đều cần dữ liệu này mà chưa có API nào trả về.

Cập nhật sau khi triển khai: phát hiện CreateDisbursement chỉ trả về ref_code ngay lập tức — approval_requests row chỉ được tạo sau đó bởi pause hook khi engine chạy tới WAIT_APPROVAL (bất đồng bộ qua outbox/worker). Maker's client vì vậy không có request id để gọi GET /v1/org/approvals/{id} ngay sau khi tạo lệnh. Đã bổ sung thêm GET /v1/org/approvals/by-ref/{ref_code} + Service.DetailByRefCode (cùng logic quyền + shape với Detail, chỉ khác khoá tra cứu) để giải quyết — xem T1b/T2b bên dưới.

2. Scope & Non-goals

Ships

  • Backend: GET /v1/org/approvals/{id} — trạng thái đầy đủ + danh sách chữ ký (tên checker, level, hành động, thời điểm), phục vụ cả maker lẫn checker xem lại.
  • Truy cập: maker (người tạo) HOẶC bất kỳ thành viên nào của org đó được xem; người không liên quan nhận 404 (không lộ sự tồn tại, đúng nguyên tắc eligibility() đang dùng cho Decide).

Non-goals (defer)

  • Chi tiết cho approval của admin (reversal / account_lock / policy_change) — web admin đã có đường riêng qua ListPendingAdminApprovals, không thuộc phạm vi endpoint này.
  • Endpoint "danh sách lệnh của tôi" cho maker — màn mobile nhận thẳng request id từ luồng tạo giao dịch/disbursement, không cần index mới.

4. Schema changes

Không có migration — approval_requests/approval_actions/organizations/transactions/users đã đủ cột, chỉ thêm query mới.

5. API changes

GET /v1/org/approvals/{id}
→ 200 { id, status, current_level, org_id, org_name, ref_code, amount, fee,
        maker_id, maker_name, created_at, expires_at, finalized_at,
        policy_name, signatures_required,
        signatures: [{checker_id, checker_name, level, action, acted_at}] }
→ 404 nếu không tồn tại hoặc người gọi không có quyền xem (existence not revealed)

Không cần ERR_* mới — dùng lại approval.ErrNotFound đã map sẵn trong errmap.go (giống Challenge/Decide hiện tại).

7. Rollout & risk
