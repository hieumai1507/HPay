2. Main flow — E15 duplicate bank callback

sequenceDiagram
  participant B as Mock Bank
  participant API as wallet.Callback
  participant DB as postgres
  participant L as ledger.Post
  B->>API: POST callback {ref_code, amount} (lần 1)
  API->>API: verify X-Mock-Bank-Secret
  API->>DB: BEGIN · SELECT txn BY ref_code FOR UPDATE
  alt txn status = created (chờ bank — enum có sẵn, không thêm giá trị)
    API->>L: Post(SYSTEM_CASH_IN → user main)
    API->>DB: txn status → completed (guarded WHERE status='created')
  else txn đã completed
    API-->>API: không đổi tiền (idempotent)
  end
  API->>DB: INSERT bank_statements (ref_code, amount, bank_ref) · COMMIT
  API-->>B: 200 {status, duplicate:false}
  B->>API: POST callback cùng ref_code (lần 2 — retry/duplicate)
  API->>DB: SELECT txn — đã completed
  API->>DB: INSERT bank_statements (row thứ 2)
  API-->>B: 200 {status:"completed", duplicate:true}
  Note over DB: Recon RunForDate (F9) thấy 2 statements cùng ref →
detail "duplicate" — đúng ngữ nghĩa E15 "ghi nhận duplicate cho recon"
  alt amount lệch với txn
    API-->>B: 422 ERR_CALLBACK_AMOUNT_MISMATCH (statement vẫn INSERT cho recon)
  end

3. Main flow — E17 Redis down

sequenceDiagram
  participant U as Client
  participant API as Gin API
  participant DB as postgres
  participant R as Redis (DOWN)
  participant RL as Outbox Relay
  U->>API: POST /transfers
  API->>DB: BEGIN · txn + workflow_instance + outbox row · COMMIT
  API-->>U: 202 Accepted (không đụng Redis trên request path)
  RL--xR: XADD fail — retry backoff, outbox row giữ nguyên status pending
  U->>API: GET /healthz
  API-->>U: 503 {redis:"down"} — degraded
  Note over R: Redis hồi phục
  RL->>R: XADD ok → consumer nhận → workflow chạy tiếp → completed

Không có state machine mới — transactions/workflow_instances giữ nguyên lifecycle; callback chỉ dùng transition guarded created → completed trên enum có sẵn. Không ERD delta (không bảng/cột mới — xem implementation plan §3 về điều kiện nới UNIQUE bank_statements nếu gặp).
