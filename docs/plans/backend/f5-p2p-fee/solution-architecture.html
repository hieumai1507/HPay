F5 P2P Transfer & Fee — Solution Architecture

1. Main flow — P2P end-to-end

sequenceDiagram
  autonumber
  actor U as User
  participant API as POST /v1/transactions/transfer
  participant T as transfer.Service
  participant E as engine (F4)
  participant W as worker handlers
  participant L as ledger.Post
  U->>API: {receiver_phone, amount, note} + Idempotency-Key
  API->>T: Transfer()
  T->>T: resolve receiver (phone→wallet), fee = fee.Calc(tier, amount)\nsoft checks: self? locked? limit? balance?
  T->>T: 1 DB tx: INSERT transactions(processing, fee)\n+ engine.Start(p2p_transfer) → outbox(VALIDATE)
  T-->>U: 202 {ref_code, fee} — app poll timeline
  W->>W: VALIDATE: user status × 2, limit, re-soft-balance
  W->>W: FRAUD_CHECK: stub safe (F9 thay thật)
  W->>L: MOVE_FUNDS: re-check status (E12) rồi Post atomic:\nDr sender (amount+fee) · Cr receiver amount · Cr SYSTEM_FEE fee
  W->>W: CONFIRM: processing → completed (guarded)
  Note over E,W: step nào fail terminal SAU MOVE_FUNDS\n→ compensation walk ngược (mục 2)

2. Compensation — walk ngược có hàng đợi

flowchart TB
  f["Step X fail terminal\non_failure = compensate"] --> q["Engine dựng queue các step\nTRƯỚC X đã completed và compensatable\n(lưu context._compensate, status=compensating)"]
  q --> d["Dispatch compensate event\n(StartEvent.compensate=true, attempt≥101)"]
  d --> h["Handler nhận StepInput.Compensating\nwallet: đảo bút toán từ txn row\nvalidator/fraud/confirm: no-op"]
  h --> r["Result event → engine (guard chấp nhận compensating)"]
  r -->|"queue còn"| d
  r -->|"queue rỗng"| done["instance = compensated\ntxn = failed (đã hoàn tiền)"]
  r -->|"compensate fail"| manual["instance = failed\nlog ERROR — admin xử lý (A3)"]

3. State — transaction với compensation

stateDiagram-v2
  [*] --> processing : transfer tạo (idempotent)
  processing --> completed : CONFIRM ok
  processing --> failed : VALIDATE/FRAUD/MOVE_FUNDS fail\n(tiền CHƯA đi - atomic MOVE_FUNDS)
  processing --> failed : step sau MOVE_FUNDS fail\n→ compensation hoàn tiền xong mới failed
  completed --> [*]
  failed --> [*]

4. Data model delta

Không đổi schema — chỉ seed (definition + fee policies). Fee chọn theo: txn_type khớp + (kyc_tier = tier của tôi ƯU TIÊN hơn tier NULL) + is_active, version mới nhất.
