2. Main flow — Nạp cấu hình & Thực thi trong KYC Scorer Step

sequenceDiagram
  autonumber
  participant ENG as Workflow Engine
  participant H as kyc_scorer handler
  participant DB as PostgreSQL (DB Pool)
  participant FC as Client Factory
  participant AI as AI API (Claude / GPT)

  ENG->>H: Execute step kyc_scorer (ctx, request_id)
  H->>DB: Query active setting for "kyc_scoring" (JOIN ai_keys)
  alt Không tìm thấy cấu hình hoặc provider = 'mock'
    DB-->>H: Trả về provider='mock', key=empty
    H->>FC: Lấy MockScorer
    FC-->>H: Trả về MockScorer
    H->>H: Tự động chấm điểm theo mã băm ảnh
  else Tìm thấy cấu hình và key active
    DB-->>H: Trả về provider='openai', model='gpt-4o', api_key='sk-...'
    H->>FC: Khởi tạo Client(provider, model, key)
    FC-->>H: Trả về OpenAIClient
    H->>AI: POST /v1/chat/completions (kèm API key + 2 ảnh base64)
    AI-->>H: 200 OK {"choices": [{"message": {"content": "..."}}]}
  else Tìm thấy cấu hình nhưng key bị disabled (is_active = false)
    DB-->>H: Trả về provider='openai', key.is_active=false
    H-->>ENG: Trả về lỗi ERR_AI_PROVIDER_UNAVAILABLE (Báo động, dừng luồng tự động)
  end
  H->>ENG: Hoàn thành, trả kết quả {score, reasons}

3. Data model — Bảng dữ liệu mới

erDiagram

    uuid id PK
    varchar name "Tên mô tả Key"
    varchar provider "anthropic | openai"
    varchar api_key "Mã API Key"
    boolean is_active "Trạng thái hoạt động"
    timestamp created_at

  }
  ai_function_settings {
    varchar function_name PK "kyc_scoring | fraud_advising"
    varchar provider "anthropic | openai | mock"
    varchar model_name "Tên model cần gọi"
    uuid key_id FK "Liên kết khóa"
    timestamp updated_at
  }

4. Decisions & trade-offs

Quyết địnhPhương án thay thếLý do & Ưu điểm
Tách bảng ai_keys và ai_function_settings Lưu thẳng api_key vào cột của bảng settings. - **Dễ dàng quản lý và tái sử dụng:** Giúp người dùng khai báo 1 API Key duy nhất (ví dụ OpenAI Key của công ty) rồi ánh xạ key đó dùng chung cho cả KYC và Fraud. Khi cần đổi key, chỉ cần sửa 1 bản ghi ở bảng `ai_keys`. - **Bảo mật:** Giúp ẩn/che trường mật khẩu dễ dàng ở các bảng quản lý.
Truy vấn DB trực tiếp mỗi lần chạy workflow step Lưu cấu hình (Cache) trên Redis hoặc in-memory. - **Tính tức thời:** Khi admin phát hiện key lỗi và bấm "deactivate", hệ thống lập tức chặn các cuộc gọi AI tiếp theo mà không cần chờ xóa cache hay đồng bộ cluster.
- **Tần suất thấp:** Các tác vụ AI như nộp ảnh KYC hay cảnh báo Fraud diễn ra với tần suất không quá lớn (vài lần mỗi giây ở quy mô vừa), do đó truy vấn trực tiếp vào PostgreSQL (được tối ưu index) không gây ảnh hưởng tới hiệu năng hệ thống.
