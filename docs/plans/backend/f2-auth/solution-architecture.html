2. Main flow — Refresh rotation + theft detection

sequenceDiagram
  autonumber
  actor C as Client
  participant API as /v1/auth/refresh
  participant S as auth.Service
  participant DB as PostgreSQL
  C->>API: refresh_token (opaque)
  API->>S: Refresh(sha256(token))
  S->>DB: SELECT by token_hash
  alt không tồn tại / revoked
    S-->>C: 401 ERR_INVALID_TOKEN
  else đã used trước đó (REUSE = token bị trộm)
    S->>DB: UPDATE revoke cả family_id
    S->>DB: INSERT audit_logs (auth.token_reuse)
    S-->>C: 401 ERR_TOKEN_REUSED — client force re-login
  else hết hạn
    S-->>C: 401 ERR_TOKEN_EXPIRED
  else hợp lệ
    S->>DB: tx: mark used_at (WHERE used_at IS NULL — chống race)\n+ INSERT token mới cùng family
    S-->>C: 200 access mới + refresh mới
  end

5. Decisions & trade-offs

Quyết địnhPhương án khácVì sao
Refresh token opaque (random 256-bit) lưu SHA-256, không phải JWTRefresh cũng là JWTOpaque revoke được từng token/family; JWT refresh không thu hồi được trước hạn
Theft detection theo familyChỉ reject token cũNếu kẻ trộm dùng token trước nạn nhân, reject đơn lẻ không cứu được; revoke family buộc re-login cả 2 phía — chuẩn OWASP
HS256 secret đơnRS256 key pair1 service tự cấp tự xác thực — không cần asymmetric; đổi sang RS256 khi tách service (interface đã che)
Login lỗi trả chung ERR_INVALID_CREDENTIALSPhân biệt user không tồn tạiChống user enumeration
Rate limit fixed-window Redis INCR+EXPIRESliding window chính xácĐủ cho mục đích; đơn giản = ít bug; nâng cấp sau nếu cần
