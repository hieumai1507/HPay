Implementation Plan — Dynamic Service Engine Dispatcher

Feature slug: service-engine-dispatcher · Phase: A (post-audit hardening) · Nguồn thiết kế: doc 05 — Offer Factory + doc 06 — Service Engine Consolidation. Đóng khoảng trống G1–G4 phát hiện trong đợt rà soát docs↔code.

1. Scope & Non-goals

Ships

  • G1 — Dynamic dispatch: ExecuteEngineRequest đọc cấu hình services theo service_code để chọn: (a) txn_type ledger, (b) workflow_definition phù hợp, (c) chiến lược resolve ví (debit source / credit target) theo service_target. Không còn hardcode p2p_transfer / TxnTypeP2p.
  • G2 — OfferGuard: middleware/service tra user_offers → offer_services enforce min_amount, max_amount_per_txn, daily_limit, monthly_limit, interval_seconds, is_enabled TRƯỚC khi tạo workflow.
  • G3 — Auth matrix từ DB: mức xác thực (pin/otp/2fa) đọc từ offer_auth_matrix theo (offer_service, amount), thay block hardcode 2M/50M ở service.go:384–389.
  • G4 — Action Pipeline executor: step handler đọc services.actions JSONB (đã tồn tại trong schema) và chạy các action GL Posting + Directional Integration (HTTP gateway) theo thứ tự action_priority (before_gl/after_gl), đi qua engine + outbox.

Non-goals (defer)

  • Admin UI để gán offer cho user (Phase B). Ở phase này chỉ cần API/seed để gán.
  • Vaults VAULT_SAVINGS end-to-end (Phase C, v2.1).
  • Thay đổi contract 3-step API — endpoint /v1/transactions/request|confirm|verify giữ nguyên (router đã prune đúng, đã xác minh).

3. Schema changes (migration 000006)

Phần lớn schema đã có (services.actions, offer_services, offer_auth_matrix trong 000003/000004). Chỉ cần bổ sung:

-- Gán gói Offer cho user (thiếu — nguồn của OfferGuard lookup)
CREATE TABLE user_offers (
    user_id    UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
    offer_id   UUID NOT NULL REFERENCES offers(id),
    assigned_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Dispatch metadata cho service (thiếu — nguồn của G1)
ALTER TABLE services ADD COLUMN workflow_name VARCHAR(60) NOT NULL DEFAULT 'p2p_transfer';
ALTER TABLE services ADD COLUMN ledger_txn_type txn_type NOT NULL DEFAULT 'p2p';
ALTER TABLE services ADD COLUMN wallet_strategy VARCHAR(30) NOT NULL DEFAULT 'user_to_user';
-- wallet_strategy ∈ {user_to_user, syscash_to_user (topup), org_to_user (disbursement)}

-- Seed map
UPDATE services SET workflow_name='org_disbursement', ledger_txn_type='disbursement', wallet_strategy='org_to_user' WHERE code='ORG_DISBURSEMENT';
UPDATE services SET ledger_txn_type='topup', wallet_strategy='syscash_to_user' WHERE code='TOPUP_BANK';
-- Backfill: gán mọi user hiện có OFFER_CUST_L2
INSERT INTO user_offers (user_id, offer_id)
  SELECT id, 'b0000000-0000-0000-0000-000000000002' FROM users ON CONFLICT DO NOTHING;

E18: make migrate-verify (up→down→up trên DB sạch) phải xanh trước khi merge. Dùng skill gen-migration để sinh cặp up/down đúng convention.

6. Rollout & risk

  • Hub symbol: ExecuteEngineRequest có blast radius rộng — chạy impact({target:"ExecuteEngineRequest", direction:"upstream"}) và báo cáo trước khi sửa (kỳ vọng HIGH). Giữ chữ ký hàm ổn định, refactor nội bộ.
  • Feature flag: ENGINE_DYNAMIC_DISPATCH (env) — false = giữ đường P2P cũ; bật dần từng service_code để rollback nhanh nếu lỗi.
  • Nửa vời: nếu merge khi T5 chưa xong, action pipeline gateway call bị bỏ qua nhưng GL posting vẫn chạy (an toàn — không mất tiền). OfferGuard fail-closed: lỗi tra cứu offer → từ chối giao dịch, không cho qua.
  • Backfill: user_offers backfill OFFER_CUST_L2 cho user cũ (idempotent).
  • Rollback: migration 000006 down xóa cột/bảng thêm; feature flag off khôi phục hành vi cũ ngay.
