Implementation Plan — Audit Log Server-Side Search

Feature slug: audit-log-search · Phần còn thiếu của "real server-side pagination, search and date filters for admin lists" (đã làm cho hầu hết list admin, audit log bị bỏ sót). Frontend (AuditPage.tsx) đã tự ghi chú rõ: "search is intentionally NOT sent — /v1/admin/audit has no text filter".

2. Scope & Non-goals

Ships

  • Backend: ListAuditLogs/CountAuditLogs lọc theo name (khớp action OR resource OR reason, ILIKE), khoảng ngày from/to trên created_at, và order — dùng lại đúng listing.Filter/CommonQueryParams.ToFilter() đã có.
  • Admin: bỏ hành vi "chỉ lọc trang hiện tại", gửi name lên server đúng như 2 trang đã làm đúng; xoá placeholder gây hiểu lầm.

Non-goals (defer)

  • Tìm theo tên/email actor (cần join admin_users/users tuỳ actor_type — actor_id hiện chỉ là UUID, không có tên để search) — để lại vì actor hiện hiển thị dạng role.uuid_ngắn, không phải tên thật.
  • UI chọn khoảng ngày (date range picker) trên AuditPage — backend hỗ trợ sẵn from/to qua listing.Filter (như mọi list khác), nhưng thêm date picker là việc UI riêng, không nằm trong yêu cầu "search" lần này.

4. Schema changes

Không có migration — chỉ đổi câu query, bảng audit_logs và 2 index hiện có (idx_audit_actor, idx_audit_action) đủ dùng cho ILIKE + created_at range ở quy mô audit log (không cần index full-text cho mức dữ liệu hiện tại).

5. API changes

GET /v1/admin/audit?name=P2P&from=2026-07-01&to=2026-07-24&order=asc&page=1&limit=10

Không có ERR_* mới — ngày không parse được thì bỏ qua (giữ nguyên hành vi ParseFromTime/ParseToTime đã có, không 400).

7. Rollout & risk

  • Rủi ro thấp: chỉ 1 endpoint admin đọc dữ liệu, không chạm ledger/workflow. Không cần feature flag.
  • Response shape không đổi (logs/total/page/limit/total_pages) — admin cũ (chưa deploy) vẫn gọi được, chỉ thiếu filter.
