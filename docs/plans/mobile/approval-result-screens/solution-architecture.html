Solution Architecture — Checker OTP Result & Conflict Screens

Song hành với implementation-plan.html. Toàn bộ state kết quả suy ra từ DecideResult (thành công) hoặc ApiError.code (conflict) — không có state UI nào tồn tại độc lập với response backend.

1. Context

flowchart LR
  A["approval-detail.tsx\nOTP modal submit"] -->|"useDecideApproval"| B["POST /approvals/:id/decide"]
  B -->|"200 {status: approved|pending|rejected}"| C["render success state\n(frame 22)"]
  B -->|"409 ERR_ALREADY_FINALIZED\n/ ERR_ALREADY_ACTED"| D["render conflict state\n(frame 23)"]
  E["order-status.tsx\nHủy lệnh"] -->|"useCancelApproval"| F["POST /approvals/:id/cancel"]

2. Main flow

sequenceDiagram
  participant U as Checker
  participant Screen as approval-detail.tsx
  participant API as POST /approvals/{id}/decide

  U->>Screen: nhập OTP, xác nhận
  Screen->>API: decide(action, otp)
  alt 200 status=approved
    API-->>Screen: {status: approved}
    Screen->>Screen: hiện "Đã duyệt — lệnh đang thực hiện"
  else 200 status=pending
    API-->>Screen: {status: pending, current_level}
    Screen->>Screen: hiện "Đã ghi nhận chữ ký — còn chờ N người nữa"
  else 200 status=rejected
    API-->>Screen: {status: rejected}
    Screen->>Screen: hiện "Đã từ chối lệnh"
  else 409 ERR_ALREADY_FINALIZED/ERR_ALREADY_ACTED
    API-->>Screen: ApiError
    Screen->>Screen: hiện state conflict + "Về hàng chờ (còn N lệnh)"
  end

3. State — UI state là ánh xạ thuần từ response, không lưu song song

stateDiagram-v2
  [*] --> Form
  Form --> SuccessLast: decide OK, status=approved
  Form --> SuccessPending: decide OK, status=pending
  Form --> Rejected: decide OK, status=rejected (chính bạn từ chối)
  Form --> Conflict: decide lỗi 409
  SuccessLast --> [*]
  SuccessPending --> [*]
  Rejected --> [*]
  Conflict --> [*]

4. Data model delta

Không có — dùng nguyên DecideResult (đã có) và ApiError.code (đã có, message tiếng Việt đã có sẵn trong src/lib/errors.ts).

5. Decisions & trade-offs

Quyết địnhPhương án khácVì sao
State cục bộ trong cùng screen, không tách routeRoute riêng /approval-resultNội dung 2 frame chỉ là thay thế phần ScrollView hiện có, không cần điều hướng/param riêng — giữ đúng mức phức tạp cần thiết
Conflict chỉ bắt đúng 2 mã ERR_ALREADY_FINALIZED/ERR_ALREADY_ACTEDCoi mọi lỗi decide là "conflict"Các lỗi khác (OTP sai, hết hạn, sai level) có copy/hành động khác hẳn (thử lại OTP, không phải "về hàng chờ") — gộp chung sẽ hiện sai thông điệp

6. Invariants touched

Không invariant tài chính — chỉ đổi cách trình bày kết quả, không đổi request/response contract của decide.
