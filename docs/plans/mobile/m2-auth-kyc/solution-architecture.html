2. Main flow — Các luồng nghiệp vụ chi tiết

A. Đăng ký & Xác thực OTP (Simulated OTP Flow)

Do backend thực hiện việc tạo người dùng và sinh JWT trực tiếp tại endpoint /v1/auth/register, app client thiết kế luồng nhập thông tin → xác thực OTP giả lập phía client → gửi API đăng ký. Thiết kế này vừa đảm bảo trải nghiệm người dùng cuối có OTP vừa khớp hợp đồng API với backend.

sequenceDiagram
  participant U as User
  participant RG as register.tsx
  participant OTP as otp.tsx
  participant API as api/client
  participant SS as session store
  participant BE as Backend (/register)

  U->>RG: Nhập Số điện thoại, Họ tên, Mật khẩu
  RG->>RG: Validate form (Zod)
  RG->>OTP: Điều hướng kèm payload thông tin đăng ký
  Note over OTP: Kích hoạt bộ đếm ngược 120s
  U->>OTP: Nhập mã OTP 6 số (e.g. 123456)
  OTP->>API: Gọi apiRequest("/v1/auth/register", payload)
  API->>BE: HTTP POST /v1/auth/register
  BE-->>API: 201 Created (user profile & token pair)
  API-->>OTP: Trả về thành công
  OTP->>SS: setSession(accessToken, user) & lưu refresh_token vào SecureStore
  OTP->>SS: Chuyển màn hình dựa vào user.kyc_status (nếu none -> kyc/intro, ngược lại -> home)

B. Luồng KYC, Client-Side Heuristic và Resume Upload (M10/M11)

Quy trình chụp giấy tờ CCCD, ảnh chân dung, thực hiện kiểm tra chất lượng ảnh thô trước khi upload và cơ chế khôi phục/tải lên tiếp khi gặp sự cố gián đoạn kết nối mạng.

sequenceDiagram
  participant U as User
  participant ID as capture-id.tsx
  participant SF as capture-selfie.tsx
  participant DR as kyc-draft store
  participant API as api/client
  participant BE as Backend (/kyc/submit)

  U->>ID: Chụp ảnh mặt trước CCCD
  Note over ID: M10: Chạy Heuristic check (độ sáng & mờ)
Dựa trên dung lượng file và metadata
  alt Ảnh không đạt chuẩn (quá tối / quá mờ)
    ID-->>U: Hiển thị toast cảnh báo và bắt buộc chụp lại
  else Ảnh đạt chuẩn
    ID->>DR: Lưu cục bộ URI ảnh CCCD vào Draft State
    ID->>SF: Điều hướng sang Chụp Selfie
  end

  U->>SF: Chụp chân dung trong khung oval
  Note over SF: M10: Chạy Heuristic check Selfie
  SF->>DR: Lưu cục bộ URI ảnh Selfie vào Draft State
  
  SF->>API: Thực thi upload multipart/form-data (CCCD + Selfie)
  alt M11: Mất kết nối mạng khi đang upload
    API-->>SF: Trả về NetworkError
    SF->>DR: Giữ nguyên URI ảnh trong SecureStore/Draft
    SF-->>U: Hiển thị lỗi kết nối kèm nút "Thử lại"
    U->>SF: Nhấn "Thử lại"
    SF->>API: Đọc URI từ Draft và upload lại
  end

  API->>BE: POST /v1/kyc/submit
  BE-->>API: 202 Accepted (Verifying workflow started)
  API-->>SF: Success
  SF->>DR: Xóa sạch bản nháp (Clear Drafts)
  SF->>SF: Điều hướng sang (kyc)/status (chế độ poll 3s)

3. State — Vòng đời trạng thái của người dùng

stateDiagram-v2
  [*] --> Unauthenticated : Chưa đăng nhập
  Unauthenticated --> Registering : Điền form đăng ký
  Registering --> OTPVerification : Xác thực mã OTP
  OTPVerification --> Authenticated : Đăng ký thành công / Đăng nhập thẳng
  
  state Authenticated {
    [*] --> KycCheck : Kiểm tra kyc_status
    KycCheck --> KycIntro : kyc_status === none & chưa skip trong session
    KycCheck --> MainHome : kyc_status !== none hoặc đã nhấn "Để sau"
    
    state KycFlow {
      KycIntro --> CapturingID : Bắt đầu xác minh
      CapturingID --> CapturingSelfie : CCCD đạt chuẩn
      CapturingSelfie --> Uploading : Selfie đạt chuẩn
      Uploading --> KycStatusScreen : Upload thành công
    }
    
    state KycStatusScreen {
      [*] --> PendingPoll : kyc_status === pending
      PendingPoll --> Verified : AI duyệt thành công
      PendingPoll --> ManualReview : Chuyển duyệt thủ công
      PendingPoll --> Rejected : Bị từ chối
      
      Rejected --> KycIntro : Nhấn "Xác minh lại"
    }
  }

  Authenticated --> IdleLocked : Không thao tác > 5 phút / background > 5 phút
  IdleLocked --> Authenticated : Vân tay/Khuôn mặt hoặc Passcode thành công

5. Decisions & trade-offs — Các quyết định kỹ thuật

Quyết địnhGiải pháp thay thếLý do & Đánh giá đánh đổi
Simulate OTP flow phía client trong lúc đăng kýBắt backend đổi APIBackend đã hoàn thiện F2. Việc giả lập đảm bảo FE có giao diện OTPInput chất lượng cao đúng spec thiết kế mà không làm xáo trộn API contract-first đã đóng băng.
