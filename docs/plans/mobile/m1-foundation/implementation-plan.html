📋 Implementation Plan — M1 Foundation mobile

Phase khởi tạo hpay-mobile. Dependency backend: chỉ F2 (Auth) — đã xong. Contract: src/backend/api/openapi.yaml v0.8.0.

1. Scope & non-goals

Ships

  • Expo SDK app (TypeScript strict), expo-router với route groups (auth)/(kyc)/(main) ở dạng placeholder + splash gate "có token?".
  • API layer contract-first: types sinh bằng openapi-typescript từ openapi.yaml của backend (script npm run gen:api), fetch wrapper tự viết mỏng gắn interceptor.
  • Auth plumbing: access token chỉ trong memory (Zustand session store), refresh token trong expo-secure-store; refresh single-flight (queue request chờ); 401 → refresh → retry đúng 1 lần; ERR_TOKEN_REUSED/revoke → force logout + event lý do (M05).
  • Headers chuẩn mọi request: Authorization, X-Device-Id (persist secure-store), X-Request-Id (uuid/request), Idempotency-Key cho POST tạo giao dịch (helper useIdempotencyKey — sinh 1 lần khi vào màn confirm, M01).
  • src/lib/money.ts: parse string→BigInt, format ngăn cách nghìn, sanitize paste — không bao giờ qua Number/float (M06).
  • src/lib/errors.ts: map tập trung ERR_* → message tiếng Việt.
  • src/lib/polling.ts: interface TransactionWatcher + poll backoff 1s→2s→4s, trần 30s → trạng thái "đang xử lý" (groundwork M02/M03; UI dùng ở M3).
  • TanStack Query provider + defaults (không retry mutation có Idempotency-Key tự động ở tầng query — retry là việc của flow).
  • Design tokens src/ui/tokens.ts đúng tên spec §2 (color/space/radius/type, tabular-nums) + primitives tối thiểu: Button (4 variant × 4 state, Loading giữ width), AmountDisplay, StatusBadge (map cứng trạng thái→màu §2.1).
  • app.config.ts base URL theo env (dev = http://localhost:8080).
  • Tooling: jest + @testing-library/react-native, eslint, scripts typecheck/lint/test/gen:api; .claude/skills/ gen-screen + gen-feature-hook; git init + .gitignore.

Non-goals (phase sau)

  • Màn hình thật Auth/KYC (M2), Home/Transfer/History (M3), Request/QR (M4), Business (M5).
  • Biometric idle-lock, cert pinning, FLAG_SECURE, root detection — gắn ở M2/M3 khi có màn nhạy cảm.
  • Maestro e2e (cần màn thật), push/deep-link handling (M08 → M5).

6. Rollout & risk

  • Repo mới, chưa release — không cần flag/backfill. Merge nửa chừng chỉ ảnh hưởng dev.
  • Risk: version matrix Expo SDK/RN/jest lệch nhau → khóa version bằng npx create-expo-app template mặc định + npx expo install.
  • Risk: openapi.yaml chưa có schema chi tiết cho vài response (mô tả text) → wrapper type hóa phần đã có schema, phần thiếu để unknown + TODO đề xuất bổ sung schema phía backend, KHÔNG tự viết tay type.
  • Rollback = revert commit; không state bền ngoài secure-store (xóa khi logout).
