2. Main flow — request có auth + 401 refresh single-flight (M04/M05)

sequenceDiagram
  participant C as Caller (hook/screen)
  participant W as api/client (wrapper)
  participant R as refresh.ts (single-flight)
  participant S as session store
  participant K as secure-store
  participant BE as backend
  C->>W: request(path, opts)
  W->>W: gắn Authorization + X-Device-Id + X-Request-Id (+Idempotency-Key nếu POST tiền)
  W->>BE: fetch
  alt 200/2xx
    BE-->>C: data (typed từ schema)
  else 401 lần đầu
    W->>R: ensureFreshToken()
    Note over R: nếu đã có refresh đang bay →
await CÙNG promise (single-flight)
    R->>K: đọc refresh_token
    R->>BE: POST /v1/auth/refresh
    alt rotate ok
      BE-->>R: token pair mới
      R->>S: set access (memory)
      R->>K: lưu refresh mới
      W->>BE: retry ĐÚNG 1 lần với token mới
      BE-->>C: data
    else ERR_TOKEN_REUSED / ERR_INVALID_TOKEN (M05)
      R->>S: clear session
      R->>K: xóa refresh
      R-->>C: throw SessionRevokedError(lý do) → router về Login, GIỮ draft
    end
  else 401 sau retry
    W-->>C: throw (không retry nữa)
  end

3. State — vòng đời session phía client

stateDiagram-v2
  [*] --> Booting : mở app
  Booting --> SignedOut : không có refresh token
  Booting --> SignedIn : có refresh → refresh thành công
  Booting --> SignedOut : refresh fail
  SignedOut --> SignedIn : login/register + OTP (M2)
  SignedIn --> Refreshing : access hết hạn (401)
  Refreshing --> SignedIn : rotate ok (retry 1 lần)
  Refreshing --> Revoked : ERR_TOKEN_REUSED / revoke
  Revoked --> SignedOut : force logout + thông báo lý do (M05)
  SignedIn --> SignedOut : user logout (POST /v1/auth/logout)
