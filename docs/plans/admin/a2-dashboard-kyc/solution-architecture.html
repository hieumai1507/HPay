📊 Solution Architecture — A2 Dashboard & KYC hpay-admin

Kiến trúc cho Dashboard tổng quan và luồng duyệt KYC (queue → detail → approve/reject). Backend đối ứng: F8 KYC + AI. Xây trên nền A1 (shell, client, store, Table).

2. Main flow — duyệt 1 hồ sơ KYC (kèm nhánh lỗi)

sequenceDiagram
  autonumber
  participant R as Reviewer
  participant Q as KYCPage (queue)
  participant D as KYCDetailPage
  participant API as /v1/admin/kyc
  participant F as /v1/files (HMAC)

  R->>Q: Mở tab manual_review
  Q->>API: GET /v1/admin/kyc?status=manual_review
  API-->>Q: [{id, user, ai_score, ai_reasons, wait_ms}]
  R->>D: Enter / click (J/K điều hướng)
  D->>F: GET ảnh CCCD + selfie (URL ký 5 phút)
  alt URL ký hết hạn (A04)
    F-->>D: 410 ERR_LINK_EXPIRED
    D->>API: refetch detail → nhận URL mới (auto 1 lần)
  else OK
    F-->>D: bytes ảnh
  end
  R->>D: Nhấn A (approve) hoặc R (reject + reason ≥ 10 ký tự)
  D->>API: POST /v1/admin/kyc/:id/review {decision, reason}
  alt Reviewer khác đã xử lý trước (A01)
    API-->>D: 409 + state mới
    D-->>R: Toast "đã được xử lý" + cập nhật row tại chỗ, không reload bảng
  else Thành công
    API-->>D: 200
    D->>Q: invalidate cache → chuyển case kế tiếp
  end

3. State — vòng đời hồ sơ KYC nhìn từ admin

stateDiagram-v2

  [*] --> auto_approved : AI tự duyệt (chỉ spot-check)
  manual_review --> approved : reviewer Approve
  manual_review --> rejected : reviewer Reject (+ reason)

4. Data model delta

Không đổi schema — đọc/ghi qua API F8 sẵn có. Cache client: query key ['kyc', status] và ['kyc', id]; mutation review invalidate cả hai.
