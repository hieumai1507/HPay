🏗 Solution Architecture — A1 Foundation hpay-admin

Kiến trúc nền cho SPA vận hành nội bộ: shell layout, auth store, API client sinh từ contract, RBAC helper. Mọi phase A2–A4 xây trên các lớp này. Tham chiếu thiết kế tổng: docs/architecture/03-admin-solution-architecture.html.

2. Main flow — login & bootstrap phiên admin

sequenceDiagram
  autonumber
  participant B as Browser
  participant L as LoginPage
  participant API as Backend /v1/admin/auth/login
  participant S as useAdminStore
  participant R as Router (RequireAdmin)

  B->>L: Mở /login, nhập email + password
  L->>API: POST /v1/admin/auth/login
  alt Sai thông tin
    API-->>L: 401 ERR_INVALID_CREDENTIALS
    L-->>B: Hiện lỗi (map từ errors.ts), không lộ chi tiết
  else Thành công
    API-->>L: 200 {access_token, role}
    L->>S: setSession(token, role) — token chỉ trong sessionStorage
    L->>R: navigate("/dashboard")
    R->>S: token hợp lệ? → render Layout Shell
  end
  Note over S,R: Token hết hạn giữa phiên → interceptor 401
→ clear store → modal re-login giữ nguyên URL + filter (A03)

3. State — vòng đời phiên admin

stateDiagram-v2
  [*] --> anonymous
  anonymous --> authenticated : login 200, lưu token + role
  authenticated --> anonymous : logout / đóng tab (sessionStorage)
  authenticated --> expired : API trả 401
  expired --> authenticated : re-login modal thành công (giữ URL)
  expired --> anonymous : hủy re-login

4. Data model delta

Không có — FE thuần, không đổi schema DB. Dữ liệu client gồm: useAdminStore (token, role — memory/sessionStorage) và cache TanStack Query (key theo endpoint + filter).
