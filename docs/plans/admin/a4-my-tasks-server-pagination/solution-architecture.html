2. Main flow — đổi trang

sequenceDiagram
  participant U as Admin
  participant T as DataTablePagination
  participant P as Page
  participant Q as useTableQueryState
  participant H as useXQueries
  participant A as Backend

  U->>T: bấm "Next"
  T->>P: table.nextPage() → onPaginationChange
  P->>Q: setPagination(pageIndex+1)
  Q-->>P: queryParams {page:2, limit:10, sort, order}
  P->>H: useXQueries(queryParams)
  H->>A: GET /v1/admin/x?page=2&limit=10
  A-->>H: {items, total, total_pages}
  H-->>P: Paged{rows, total}
  P->>T: pageCount = ceil(total/limit), totalCount = total
  Note over T: chỉ render `limit` hàng của trang 2

3. Main flow — quyết định approval (My Tasks)

sequenceDiagram
  participant U as Admin (ops/superadmin)
  participant M as MyTasksPage
  participant D as useDecideApproval
  participant A as Backend

  M->>A: GET /v1/admin/approvals?status=pending
  A-->>M: {approvals, total}
  U->>M: chọn 1 lệnh → Approve/Reject + lý do
  alt thiếu quyền
    M-->>U: nút bị ẩn (can() = false)
  end
  M->>D: decide({id, action, reason})
  D->>A: POST /v1/admin/approvals/:id/decide
  alt 409 ERR_ALREADY_FINALIZED
    A-->>D: 409
    D-->>M: toast "đã được chốt bởi người khác" + invalidate list
  else 200
    A-->>D: ok
    D-->>M: invalidate list → hàng biến mất khỏi inbox
  end

6. Decisions & trade-offs

Quyết địnhPhương án khácVì sao
Offset pagination (page/limit)Cursor pagination như doc 07 gợi ýBackend đã hiện thực offset và trả total_pages; đổi sang cursor là thay đổi backend ngoài scope. Ghi nhận nợ: offset có thể trôi hàng khi dữ liệu chèn giữa lúc phân trang
Paged<T> thay vì trả mảng phẳngTrả mảng + hook riêng lấy totalMột nguồn sự thật cho pageCount; compiler bắt được mọi call site khi đổi
total fallback rows.lengthBắt buộc API trả totalKhông vỡ khi endpoint chưa nâng cấp hoặc backend revert
Đổi từng hook mộtRefactor đồng loạtBảng là hạ tầng dùng chung; đổi dần + tsc giữ repo luôn build được
My Tasks dùng lại DataTableBảng riêngĐồng nhất UX phân trang/sắp xếp với các queue khác
