# 📋 Implementation Plan — M1 Foundation mobile

Bootstrap phase for `hpay-mobile`. Backend dependency: **only F2 (Auth)** — already done. Contract: `src/backend/api/openapi.yaml` v0.8.0.

## 1. Scope & non-goals

### Ships

- Expo SDK app (TypeScript `strict`), expo-router with route groups `(auth)`/`(kyc)`/`(main)` as placeholders + a splash gate "has a token?".
- Contract-first API layer: types generated by `openapi-typescript` from the backend's openapi.yaml (script `npm run gen:api`), a thin hand-written fetch wrapper with interceptors attached.
- Auth plumbing: access token **only in memory** (Zustand session store), refresh token in `expo-secure-store`; refresh is **single-flight** (waiting requests are queued); 401 → refresh → retry **exactly 1 time**; `ERR_TOKEN_REUSED`/revoke → force logout + a reason event (M05).
- Standard headers on every request: `Authorization`, `X-Device-Id` (persisted in secure-store), `X-Request-Id` (uuid/request), `Idempotency-Key` for POSTs that create transactions (helper `useIdempotencyKey` — generated once when entering the confirm screen, M01).
- `src/lib/money.ts`: parse string→BigInt, thousands-separator formatting, paste sanitization — **never goes through Number/float** (M06).
- `src/lib/errors.ts`: centralized map of `ERR_*` → Vietnamese message.
- `src/lib/polling.ts`: `TransactionWatcher` interface + poll backoff 1s→2s→4s, capped at 30s → "processing" status (groundwork for M02/M03; UI used in M3).
- TanStack Query provider + defaults (no automatic retry of mutations carrying an Idempotency-Key at the query layer — retry is the flow's job).
- Design tokens `src/ui/tokens.ts` with the exact names from spec §2 (color/space/radius/type, tabular-nums) + minimal primitives: `Button` (4 variants × 4 states, Loading keeps width), `AmountDisplay`, `StatusBadge` (hard-coded status→color map §2.1).
- `app.config.ts` base URL per env (dev = `http://localhost:8080`).
- Tooling: jest + @testing-library/react-native, eslint, scripts `typecheck`/`lint`/`test`/`gen:api`; `.claude/skills/` gen-screen + gen-feature-hook; git init + .gitignore.

### Non-goals (later phases)

- Real Auth/KYC screens (M2), Home/Transfer/History (M3), Request/QR (M4), Business (M5).
- Biometric idle-lock, cert pinning, FLAG_SECURE, root detection — attached in M2/M3 when sensitive screens exist.
- Maestro e2e (needs real screens), push/deep-link handling (M08 → M5).

## 6. Rollout & risk

- New repo, not yet released — no flag/backfill needed. A half-way merge only affects devs.
- Risk: the Expo SDK/RN/jest version matrix drifting apart → lock versions via the default `npx create-expo-app` template + `npx expo install`.
- Risk: openapi.yaml lacks detailed schemas for a few responses (text descriptions only) → the wrapper types the parts that have a schema, leaves the missing parts as `unknown` + a TODO proposing that the backend add the schema, and does NOT hand-write types.
- Rollback = revert the commit; no durable state beyond secure-store (cleared on logout).
