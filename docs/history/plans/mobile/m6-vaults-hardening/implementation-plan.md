## 4. APIs used

```
GET  /v1/vaults                                  → list of vaults
POST /v1/vaults {label, target_amount?}          → create a vault
POST /v1/transactions/request                    → deposit/withdraw
  { service_code:"VAULT_SAVINGS", amount,
    extra_params:{ vault_id, direction:"deposit"|"withdraw" } }
POST /v1/transactions/confirm { transaction_id, pin }

```

Money still goes through exactly the 3-API engine set — mobile calls **no** dedicated money endpoint for vaults.

## 6. Rollout & risk

- **Backend dependency**: T1–T4 cannot run until `vaults-engine` is merged. Do T5/T6 first so as not to be blocked.
- `expo-screen-capture` needs a **native build** — it does not work in Expo Go. Must be checked on a dev build, and wrapped in try/catch so Expo Go does not crash.
- Do not show a RoundUpToggle while the backend does not have it — better missing than a switch that does nothing.
- Rollback: purely UI + 1 package, reverting the commit is enough.
